# Phase 47 — 伺服器權威報價契約模型

## 本階段交付
- 建立報價 reference model：商品價格只從伺服器可信商品快照取得。
- 配送費只從伺服器可信費率快照取得；不接受前端傳來的價格、運費或總額作為依據。
- 報價包含 quote ID、版本、幣別 TWD、商品明細、商品小計、配送費、總額、建立時間、到期時間及購物車指紋。
- 涼糕 chilled 與蘿蔔糕 frozen 配送方式各自驗證，不可混用。
- 停售、未開放網購、缺價、缺運費設定、錯誤配送方式、無效數量及收件資料不完整均拒絕報價。
- 報價驗證檢查有效期限、配送方式與購物車指紋，購物車改變須重新報價。
- 金額以整數最小貨幣單位保存，避免浮點運算誤差。

## 安全邊界
此為純 Node reference model。正式系統必須由受信任的伺服器端程式讀取商品價格、上架狀態、物流費率及時間，並保存／簽署報價紀錄；不能讓瀏覽器或 App 自己提供可信 catalog/rates，也不能只靠 client 傳回的 quote JSON 判斷真偽。正式結帳時伺服器仍須重新查詢 quote ID、有效期限、版本、使用狀態與購物車內容，並在同一交易中建立訂單。Phase 47 尚未實作簽章、資料庫保存、一次性消耗或訂單交易。

## 限制
- 使用合成商品與費率測試資料，不代表實際核定售價或運費。
- 沒有連線正式 Supabase、物流商、付款或訂單 API。
- 不建立訂單、不收款、不部署、不修改官網。
- 本階段不是正式報價 API，也不是可安裝 App。
