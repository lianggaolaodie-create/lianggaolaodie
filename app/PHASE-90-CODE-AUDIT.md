## 2. 重要發現

### A-01 — Phase 88 功能未能在目前檢查的首頁程式碼中驗證

檢查 `index.html` 時，未找到以下字串或實作標記：

- `DEMO-1002`
- `DEMO-1003`
- 訂單追蹤介面相關文字
- 配送方式預覽相關文字
- Phase 88 標記

**影響：** 不能以官方網站首頁程式碼證明 Phase 88 已實際部署或已整合至 App。Phase 88 目前只能依本專案工作紀錄視為已描述完成，仍需取得實際 App 檔案或可測試網址才能回歸驗收。

**處理：** Phase 88 回歸測試保持「待執行」，不可標記通過。

### A-02 — App 程式碼與可建置專案尚未出現在目前可驗證範圍

`app/README.md` 與架構文件明確描述專案仍在規劃、資料盤點階段；文件列出的會員、顧客、PDA、後台功能屬目標架構，不代表已經有可執行功能。

**影響：** 暫時無法執行 App 安裝、打包、單元測試、端對端測試、iPhone/PDA 相容性測試。

**處理：** 需要先將實際 App 原始碼、依賴鎖定檔、建置說明及測試設定放入指定分支，或提供可驗收的示範 App 預覽網址。

### A-03 — 官網首頁仍是既有獨立網站程式

`index.html` 包含既有官網導覽、首頁行程載入及 Supabase 讀取程式。它不是可直接等同於顧客 App、員工 PDA 或老闆後台的完整實作。

**影響：** 不應把修改官網首頁當作完成 App 整合；也不應為了測試 App 而改動正式網站頁面或正式資料。

**處理：** 維持官網原狀，待 App 沙盒程式與整合 API 準備完成後再做獨立整合測試。

### A-04 — 正式資料連線尚不具備本階段啟用條件

架構文件列出既有資料表名稱及安全要求，但本次未對正式 Supabase 執行 schema/RLS 查詢，也未操作任何正式資料。

**影響：** 尚不能確認實際欄位、外鍵、RLS、Storage policies、付款流程及資料一致性。

**處理：** 本階段不得連接或寫入真實顧客資料、正式訂單、付款或物流資料。日後須以獨立測試環境、合成資料及最小權限完成安全盤點。

## 3. 安全檢查原則

- 本次未執行正式資料庫查詢或修改。
- 本次未啟用付款、退款、正式結帳或物流 API。
- 本次未變更官網首頁或部署設定。
- 不將公開前端 publishable key 誤判為 service-role secret；但仍須在正式安全稽核中檢查所有環境變數與部署設定，確認沒有任何 secret 洩漏。
- 所有 Phase 88 / 89 測試資料必須為合成示範資料，禁止使用真實顧客姓名、電話、地址或正式訂單編號。
