# Phase 28｜合成測試資料字典與整批驗收矩陣

日期：2026-11-08  
分支：`app/phase-1-planning`  
狀態：測試規格與虛構資料字典；尚未執行 Supabase 整合測試。

## 1. 測試安全原則

- 全部資料均為虛構，不使用正式會員、顧客、訂單、電話、地址、付款證明或 LINE token。
- 測試環境只能使用 localhost Supabase；未來若非本機環境，必須先取得明確同意並確認費用。
- 所有 LINE 發送使用 mock transport，不發送真實訊息。
- 不以測試規格或 mock 通過結果代表正式環境驗收。
- 不修改正式 Supabase、Storage、Edge Functions、Secrets、LINE 或官網。

### 2.2 個資與檔案規則

- 測試電話使用保留測試格式，不可撥打真實電話。
- 地址使用明確標記為測試的虛構地址，不用真實客戶地址。
- 測試圖片由程式產生的純色／文字 fixture 檔組成，不使用真實匯款截圖。
- 不把測試 token、假密鑰或任何 Secret 寫入 Git。
- 上述 Fixture ID 是測試識別碼，不代表資料已 seed 至任何資料庫。

## 4. 執行分類與完成定義

| 分類 | 可以先做什麼 | 完成證據 |
|---|---|---|
| 靜態規格檢查 | 文件、schema 對照、caller matrix | 審閱紀錄 |
| 純函式測試 | 狀態轉換、資料驗證、HMAC helper | 可重現測試輸出 |
| Mock 測試 | LINE、付款 webhook、物流 provider | 假服務請求／回應 |
| DB 整合測試 | migration、RPC、RLS、GRANT、併發交易 | 本機 Supabase 實測 |
| Storage 整合測試 | private bucket、signed upload、finalize | 本機 Storage 實測 |
| Edge Function 整合測試 | Deno runtime、JWT／HMAC、錯誤處理 | 本機 runtime 實測 |
| 裝置測試 | iOS／Android 真機或模擬器 | 裝置／版本測試紀錄 |
| 正式上線驗收 | 備份、部署核准、灰度、回復 | 明確核准及部署紀錄 |

## 5. 阻擋項目與依賴

1. 使用者目前只有 iPhone；無法在手機上啟動 Docker 與本機 Supabase stack。
2. 正式資料庫／Edge Function／Storage 的整合測試仍未執行。
3. 外部 caller、實際後台入口、正式物流合約及費率仍有待管理者確認。
4. App Store／Google Play 上架需開發建置、簽章、開發者帳號及審核。
5. 不得為繞過設備限制而擅自建立付費雲端測試環境。
