# Phase 89 — 全功能整合與上線前驗收

> 狀態：驗收規格已建立；實際執行結果須逐項測試後填寫，不可將「規格完成」視為「功能通過」。
> 分支：`app/phase-1-planning`
> 視覺：曜石黑、香檳金、暖白（繁體中文）
> 本階段模式：示範資料 / 沙盒驗收；正式結帳維持停用。

## 0. 不可違反的安全邊界

- 不查詢、匯入、修改或展示真實顧客個資及正式訂單。
- 不啟用正式結帳、收款、退款或付款回呼。
- 不連接真實物流商、不建立真實託運單、不宣稱物流已串接。
- 不修改正式官網、正式 Supabase 資料表、既有訂單或顧客資料。
- 不將示範單號或示範狀態混入正式資料。
- 任何未實際執行的測試標記為「待執行」，不可標成通過。

## 4. 餐車與擺攤驗收

- [ ] 出攤日期、服務地區、時間及場次顯示正確。
- [ ] 當日販售口味可檢視；公開價格設定與內部管理價格分離。
- [ ] 擺攤公開頁不顯示內部價格欄位。
- [ ] 餐車線上訂單與現場臨時單能清楚區分。
- [ ] 行程變更、取消、售完等示範狀態有明確標示。
- [ ] 全部測試使用合成資料，不寫入正式行程或訂單。

## 5. 老闆後台驗收

- [ ] 訂單總覽能區分示範訂單來源與狀態。
- [ ] 商品、口味、價格管理只使用示範資料。
- [ ] 庫存異動、出貨核對及操作紀錄可追蹤示範操作人與時間。
- [ ] 員工角色及權限頁面有越權拒絕測試。
- [ ] 報表數字能由示範資料重算，且標示為示範報表。
- [ ] 不提供真實顧客個資查詢入口，不連正式資料庫。

## 6. 跨模組整合驗收

- [ ] 顧客端示範購物車資料可安全傳至示範訂單預覽，不建立正式訂單。
- [ ] 訂單追蹤頁只讀取固定示範資料集。
- [ ] PDA 與後台的示範狀態定義一致。
- [ ] 餐車現場單與線上示範單的來源標記一致且不混淆。
- [ ] 導覽、返回、重新整理、空狀態、錯誤狀態皆有明確處理。
- [ ] iPhone 小螢幕與桌面版主要流程無水平溢位或按鈕遮擋。

## 7. 上線阻擋條件（全部解除前不得正式上線）

1. 正式會員/Auth、RLS、資料表 schema 與權限尚未完成安全盤點。
2. 正式訂單建立、付款驗證、退款及付款回呼尚未完成端到端測試。
3. 物流供應商、運費規則、託運單與物流狀態同步尚未整合。
4. 官網、App、PDA、後台的正式 API 與資料一致性尚未驗證。
5. Apple / Google 商店要求、隱私政策、服務條款、客服資訊與上架素材尚未驗收。
6. 備份、復原、監控、錯誤回報及正式環境回復計畫尚未演練。

## 9. 本階段完成定義

Phase 89 的文件與測試案例建立，不等於整套 App 已完成整合或可正式上線。只有所有適用測試有可重現的執行紀錄、阻擋問題修正並完成回歸測試，才能宣告示範版驗收通過。正式會員、付款、物流及真實訂單整合另需獨立安全驗收與明確啟用程序。
